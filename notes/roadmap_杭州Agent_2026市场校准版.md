## 1.1 Agent 架构思维与「人能维护」素养【更新·回应门外汉直觉】

你的担心是对的，而且**正是这份工作要解决的问题**：现在多数 Agent 一次生成的东西，常常难读、难测、难改——所以公司招的是「能把 Agent 关进可维护流程里的人」，不是「会按一次生成按钮的人」。

原清单里已有相关碎片（Context / Skills / 评测 / 三个故事），但**没写成独立训练项**。现补进清单：

| 素养 | 何时练 | 你要能做到 |
|------|--------|------------|
| **问题拆解** | A 尾声起（写 dca-ledger 时） | 先写「输入/输出/失败时怎么办」，再写代码；不用 Agent 也能自己列出 5 条验收标准 |
| **规格先于代码** | B 起正式练 | 先用对话模型把需求聊准 → 产出一页规格（目标、边界、非目标、验收）→ 再交给编码 Agent（Cursor/Codex） |
| **架构最小集** | B | 能画并讲清：用户 → 编排/路由 → 工具(Tool) → 记忆/检索(RAG) → 评测；知道哪一步最容易烂 |
| **人必须能维护** | B→D | 每个模块有边界；关键逻辑你能读懂；有 BadCase 表；改一处能回归测；README 写清「怎么跑、怎么挂、怎么修」 |
| **双角色协作** | B 起养成习惯 | 「规格 Agent/聊天」负责澄清；「编码 Agent」负责实现；**你**负责验收、拒绝糊弄、亲手改关键路径 |
| **工具可换** | 全程 | 今天 Cursor，以后 Codex/Claude Code 都一样：差在工作流，不在品牌 |

**推荐工作流（阶段 B 起采用，现在用 Cursor 也可预习）：**

1. 用一个擅长聊天/推理的模型，把需求聊到「无歧义」（多问边界：不要什么、坏了怎么表现）。  
2. 你（或同一模型）**总结成规格**：功能列表、文件结构建议、验收命令、禁止事项。  
3. 把规格交给 **Codex / Cursor Agent** 写代码。  
4. 你跑通 + 读 diff + 补测试/评测；糊的地方打回重做或手改。  
5. 把反复踩坑写成 Skill / README——这就是「可维护」的证据。

**一句话定位：** Agent 应用工程师 = 会用 Agent 加速，但**对人、对仓库、对线上行为负责**的人；不是把维护责任甩给模型。

## 1.2 计划饱满度 + 两段实习能力对照【更新】

### 计划是否「完全饱满」？

对你这种 **每天约 2 小时、双非软工、目标应用岗** 的节奏：**主路径已经够满，再加第三条主线会挤爆。**

| 判断 | 说明 |
|------|------|
| **够用** | A→F 阶段、JD 证明物、公司分层、笔试、Java、Skill、协作素养都已对齐 2026-09 市场 |
| **不要再加的主线** | 前端全栈、训练大模型、竞赛 ACM 当主业、同时深挖 3 个框架 |
| **允许微调的支线** | 课表变动时挪 Java 学期；实习拿到手后按组内技术栈微调（MCP/内部框架） |
| **本轮唯一实质性补强** | 把「第一段 / 第二段实习分别要会什么」写成硬对照（见下表），避免期望虚高 |

结论：**不是百科全书式饱和，是求职路径饱和。** 执行到位即可投；缺的是执行，不是再开十个专题。

### 第一段实习（阶段 D，约 2027 暑假）— 入场要会什么

对应准备完成阶段：**A + B + C**（投递时 B 出口必须达标）。

| 维度 | 入场应达到（面试能证明） | 实习期间再学（组内教） |
|------|--------------------------|------------------------|
| Python/工程 | 独立 CLI/小服务、Git、venv、读报错 | 公司仓库规范、内部库 |
| Agent 最小闭环 | **单 Agent**：多轮 + Tool 调用 + 简单 RAG + 10 条评测 | 业务 Prompt、内部评测平台 |
| 架构 | 能画并讲清「用户→工具→检索→输出→评测」五块 | 公司真实链路、权限与安全 |
| 框架 | LangChain **或** Dify 跑通过，能讲取舍 | 可能换内部框架，方法可迁移 |
| Skills/协作 | 2–3 个 Skill；会「规格→编码 Agent→你验收」 | 组内文档与 Code Review |
| 多 Agent | **知道概念**（何时拆成两个角色），**不要求**上岗前就会搭生产级多 Agent | 若组里有编排，跟做 |
| Java/笔试 | 课内进度即可，不挡第一段 | 继续跟课 |
| 目标心态 | 「我能交货、能改 BadCase、能维护自己的模块」 | 不是「我一人设计中台」 |

**第一段合格线一句话：** 你会做**可维护的单 Agent 应用切片**，不是会造平台。

### 第二段实习（阶段 E，约 2027 冬–2028 夏）— 应达到什么

对应准备完成：**D 复盘 + E 前半加深**（投二段前最好已做完「编排或 Memory」二选一实验）。

| 维度 | 第二段入场应达到 | 不要自我绑架的目标 |
|------|------------------|--------------------|
| 架构思维 | **能独立讲清并画图**：路由/编排、工具协议、状态/记忆、失败重试、评测回归 | 不必能写论文级 Agent 理论 |
| 手搓能力 | **能手搓一个最小编排**：至少 2 个角色（如「计划/工具」或「检索/回答」）+ 共享状态或明确交接 + 一套评测；可用 LangGraph **或** 自己写循环，不要求从零造框架 | 不必手搓媲美阿里内部的 Agent 中台 |
| 多 Agent 做项目 | **起码做过 1 个多 Agent（或清晰 Subagent）小项目**，简历能写清：谁干什么、怎么交接、哪步会烂、你怎么测 | 不必「所有项目都多 Agent」；单 Agent 做深也加分 |
| 工程 | 有一段脱敏实习复盘；Linux/Git/SQL 不慌；Java 能看懂简单接口 | 不必成后端专家 |
| 协作 | 规格→Codex/Cursor→验收 已成肌肉记忆；能带简单 BadCase 流程 | 不必带团队 |

**第二段合格线一句话：** 你**懂架构、能手搓最小多 Agent、能用多 Agent 做完一个小项目并维护**；上岗后接公司更大系统，而不是上岗前就已经「什么都能一手包办」。

### 阶段 ↔ 实习对照（背这张）

```text

阶段 E 加深     → 手搓/跑通多 Agent 编排 + 笔试 + Java 对齐
阶段 E 二段实习 → 带着「架构 + 多 Agent 作品 + 一段实习」冲蚂蚁/淘天/阿里云/字节
阶段 F         → 秋招收口
```

**直接回答你的三个担心：**

1. **计划还要不要再塞？** 主线不用再塞；缺的是按表执行与实习后按组内栈微调。  
2. **第一段要会什么？** 单 Agent 可维护闭环 + 能讲架构五块 + 评测；**不要求**上岗前就会多 Agent 搭项目。  
3. **第二段是不是该懂架构、能手搓、会用多 Agent 做项目？** **是**——这是 E 的出口标准；标准是「最小可演示的多 Agent 项目」，不是「一人重建大厂 Agent 平台」。
