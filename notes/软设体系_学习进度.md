## 规划怎么更合理（已定）

### 学校上课顺序（跟课表）

`Ch1 → Ch2 → Ch3 → Ch4 → Ch5`

### 自学对话顺序（同一内容，认知更顺）

| 阶段 | 做什么 | 为什么 |
|------|--------|--------|
| A | **Ch1 全** + **Ch3 直觉预告**（内聚/耦合/分层各一句+例子，不深挖） | 先知道「为什么设计、拆什么」 |
| B | **Ch2 UML**（此时画图有东西可画） | 避免空画图 |
| C | **Ch3 正式加深** | 图和原则互相印证 |
| D | **Ch4**（例子：Python 类 / ledger；Java 进 OOP 后再对照加深） | 与 Java 进度解耦，不卡死 |
| E | **Ch5** 作对比章 | 答辩常问两种思路差别 |
| F | **答辩串讲** 2～3 次口述 | 期末形式决定备考重心 |

老师若强制「这周必须交 Ch2 作业」→ **作业优先**，临时插入，不打乱总目标。

### 和其它课怎么错开

| 软设 | 依赖/配合 |
|------|-----------|
| Ch1–Ch3 | 几乎不依赖 Java；用生活例子 + ledger 即可 |
| Ch4 | Java 仍在 W01 语法期 → 用 Python；Java 进入「类/继承」后加一次对照课 |
| Ch5 | 不要求会写很多代码；认 DFD + 能对比即可 |
| 答辩周 | 可临时压缩 Python 日课 1～2 天，专攻口述+图 |
| 软工导论（并行） | 生命周期/DFD/内聚耦合/OOP：软设深讲；导论课上跟教材用语与作业即可 |

### 一节课剂量（skills）

- **主概念只 1 个**（例如今天只讲「用例图」或只讲「耦合」）  
- 懵了：降到生活类比（simplify），确认后再加回术语  
- 反复错：记入错题本，下节先花 5 分钟纠，不急着开新章  
- 结束必有：1 道口述题 + 1 个小任务（草图/改拆分/答辩一句）

## 五章细分 + 勾选

### 第一章 · 软件工程与软件设计

**答辩句：** 软件工程是把软件当工程做；设计是写代码前把怎么拆、怎么搭想清楚。

| 小节 | 讲什么 | 你会 |
|------|--------|------|
| 1.1 | 为什么需要工程（难改、难协作、易延期） | 举 1 个「堆成一团」的痛 |
| 1.2 | 软件工程：方法+过程+工具；生命周期阶段 | 按序说阶段 + 各干什么 |
| 1.3 | 设计在流程中的位置；概要 vs 详细设计 | 能区分设计与编码 |
| 1.4 | 质量：可维护/可理解/可修改等（跟老师用词） | 能说「为了 ___ 所以这样设计」 |
